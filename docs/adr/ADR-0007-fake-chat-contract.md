# ADR-0007: M3 채팅 계약과 제한된 복구

- 상태: 채택; 사용자 지정 한도: 보관 1,000개·표시 500개·메시지당 1,000 Unicode 코드포인트.
- 결정: UI와 ViewModel은 ChatTransport 계약만 사용한다. Fake 구현은 고정 seed와 coroutine 시간으로 재현한다. 확정된 연속 sequence와 관측된 최댓값을 분리하고 누락 구간은 페이지 단위로 보충한다. 결과 불명 전송을 임의로 Failed 처리하지 않는다.
- 경계: 채팅 소유권은 상세 화면의 ViewModel이며 화면 이탈·룸 전환에서 취소한다. Media3 Player의 소유권과 작업은 별도다. 화면과 Fake 서버가 공유하는 논리 메시지 예산은 합계 1,000개를 넘지 않으며 미확인 전송이 공간을 차지하면 새 전송을 거절해 기존 메시지를 조용히 버리지 않는다.
- 대안과 제한: 단순 최고 sequence만 저장하는 방식은 역순 수신 시 중간 누락을 감추므로 제외한다. 제한된 Fake 이력을 벗어난 누락은 자동 복구를 주장하지 않고 오류로 표시한다. 영속화와 실 서버의 순서·보관 계약은 M4에 남긴다.

Fake 서버의 중복 요청 멱등성은 공유 예산 안에 보관 중인 ID에 적용된다. 퇴출된 ID의 장기 중복 방지는 M4 서버의 영속 계약으로 남긴다. 개수·문자열 길이는 제한하지만 JVM 객체·비디오·런타임까지 포함한 프로세스 전체 바이트 상한을 주장하지 않는다.
