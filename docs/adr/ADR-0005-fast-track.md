# ADR-0005: Fast Track v1 개발 운영

- 상태: ACCEPTED — 2026-11-04 사용자 사전 승인; 검증 결과와 별개
- 범위: M0~M8; M9 제외. ADR-0001의 단계별 별도 승인 요구를 대체한다.

## 결정과 이유

SDD → 기능 구현·테스트·리뷰 → PR → 병합을 한 단위로 묶고, 사전 승인된 M0~M8에서는 핵심 게이트 통과 후 다음 작업을 진행한다. 관련 문서와 실행 증거는 기능 PR에 포함한다. 변경 영향이 없는 검증은 근거와 함께 재사용하거나 NOT_RUN으로 기록하여 중복 작업을 줄인다. 실제 검증 결과와 과거 실패·이력은 보존한다.

## 품질과 중단 조건

P0: 컴파일·핵심 테스트 실패, 시크릿 노출·중대한 보안 취약점, 데이터 정합성 오류, 명백한 리소스 누수, 승인 범위 밖 구현은 반드시 차단한다. P1: 해당 기능에 영향을 주는 Player/Surface/Listener 해제, coroutine 취소·오래된 응답, 채팅 ACK·중복·역순·누락, 네트워크 복구·재진입과 핵심 흐름은 기능 완료 전 검증하며 실패·미검증이면 차단한다. P2: 경미한 lint·문구·미관·비차단 리팩터링과 현재 단계에 무관한 선택 검증은 추적 가능한 후속 작업으로 이월할 수 있다. M8에서 이월된 중요한 검증을 다시 평가한다. 기존 마일스톤의 필수 기능과 해당 Gate는 삭제하거나 PASS로 추정하지 않는다.

## 승인 및 미결정

사용자는 M0~M8 개발과 GitHub commit/push/PR/merge를 사전 승인했다. 외부 상시 과금 인프라, 신규 보안 자격 증명과 비가역 외부 작업은 별도 승인받는다. 기능 범위·사용자 흐름·보존 기준 등 목표에 중대한 미결정은 기본값으로 확정하지 않고 사용자에게 질문하며 독립 작업은 계속한다. 품질 게이트를 끄거나 실패를 무시하지 않는다.

## 대안과 트레이드오프

매 단계마다 별도 승인·문서 PR을 요구하는 방법은 관리가 명확하지만 대기와 중복 검증이 늘어난다. 무조건 자동 병합은 빠르지만 검증 실패를 놓칠 수 있다. Fast Track은 기능별 리뷰·영향 기반 검증을 유지하면서 이월 내역의 추적 책임과 M8 재평가 비용을 감수한다.
