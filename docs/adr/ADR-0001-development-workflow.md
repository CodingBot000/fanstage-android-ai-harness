# ADR-0001: SDD와 증거 기반 개발 워크플로

- 상태: ACCEPTED — 2026-11-04 사용자 포괄 승인 (실행 검증과 별개)
- 범위: 개발 프로세스; 앱 아키텍처 확정 아님

## 배경과 결정안

한 작업의 승인 범위와 실제 결과를 추적하기 위해 SDD에 목표·계약·수용 기준을 두고, 현재 상태와 실행 증거를 각각 STATUS와 build-log에 기록한다. 공통 불변 규칙은 AGENTS.md에 두고 CLAUDE.md는 이를 import한다. 사람의 리뷰와 승인을 작업 및 마일스톤 전환 게이트로 둔다.

## 이유와 대안

문서 없이 프롬프트와 기억에만 의존하면 범위 이탈과 실행 근거 유실을 추적하기 어렵다. 도구별 지침을 복제하면 규칙이 서로 달라질 수 있어 공통 원본을 선택했다. 모든 검증을 사람에게만 맡기는 대신 실행 가능한 검증과 사람의 판단을 함께 사용한다.

## 트레이드오프

문서 유지 비용과 도구별 import 호환성 검증이 필요하다. 지침은 자동 차단 장치가 아니므로 향후 승인된 작업에서 실제 테스트와 CI 게이트를 연결해야 한다. AI 리뷰는 사람의 승인이나 테스트를 대체하지 않는다.

## 주 실행 에이전트 결정

- Codex CLI/Cloud 및 공식 GitHub Action을 주 구현·검증 경로로 선택한다.
- `CLAUDE.md`는 선택 호환성 파일로 유지하며 M0 필수 게이트로 운영하지 않는다.
- Secret은 GitHub Actions의 `OPENAI_API_KEY`로만 참조하고, 공개 PR 작성자가 실행 코드를 주입하는 경로에서 사용하지 않는다.
- AI가 다음 작업을 계획할 수 있어도 검증 실패 상태에서 단계 완료를 확정하지 않는다.
