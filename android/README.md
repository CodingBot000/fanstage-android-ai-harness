# M1-002 Android foundation

Only `:app`, `:feature:live`, and the Kotlin/JVM `:core:model` module are included.
The app owns navigation and constructs the fake repository and ViewModel factory.
The feature exposes the model dependency because its public state and factory use
the model contract. The model has no Android, UI, storage, or networking dependency.

The room list supports loading, content, empty, and error with retry. The default
fake always returns three fictional rooms; unit test repositories cover empty and
failure results. Detail contains only video/chat placeholders. Row clicks navigate
to detail, and the back button/system back return to the retained list entry.

## Separate CI setup and verification

Build, lint, unit tests, and device checks: **NOT_RUN** during source generation.
No binaries or SDKs were downloaded. Wrapper properties pin Gradle 9.5.0; wrapper
scripts and the wrapper JAR must be generated by the subsequent trusted setup job.
From `android/`, using JDK 17 and the Android SDK platform 37:

```sh
gradle wrapper --gradle-version 9.5.0 --distribution-type bin
./gradlew clean :app:assembleDebug :app:lintDebug :feature:live:lintDebug :feature:live:testDebugUnitTest :core:model:test
```

`gradle` in the first command must be the Gradle 9.5.0 installation supplied by CI.
No Android Kotlin plugin is applied; AGP provides built-in Kotlin, while each
Compose module applies the Kotlin Compose compiler plugin. The pure JVM model
uses the Kotlin JVM plugin.

AGP 9.3.3, Kotlin/Compose compiler 2.4.21, and Compose BOM 2026.09.00 remain
unverified candidates. Kotlin's documented fully supported AGP range ends at
9.3.1. AndroidX Activity 1.12.4, Lifecycle 2.10.0, Navigation 2.9.7, and coroutines
1.10.2 are pinned stable selections; artifact resolution and compatibility still
require CI. Do not infer a passing build from these version pins.

Unit tests use a virtual coroutine scheduler for repository snapshots, initial
loading/content, empty, error/retry, superseded requests, and ViewModel clearance.
Device verification still needs installation, list/detail/back navigation,
rotation, and semantic tags (`rooms_loading`, `rooms_content`, `rooms_empty`,
`rooms_error`, `rooms_retry`, `room_detail`, `room_back`). No device/UI test result
is claimed. No M1-003 workflow or later milestone functionality is included.
